# 交稿与连续性

## 一、文件与格式

- 全部使用 UTF-8、Markdown。
- 正文：`chapters/` 下，沿用第〇回的做法（如 `chapters/01_古道斜阳人语断.md`，或用户指定的文件名）。标题行：
  `# 第X回　上句　下句`
  两句七言，中间一个全角空格；与 `outlines/10_全书分回索引.md` 一致。
- 卷纲与分回：写回 `outlines/0X_第X卷大纲.md`，回目或回次变动时同步更新 `outlines/10_全书分回索引.md`。
- 审校与读书记录：`reviews/YYYY-MM-DD_主题.md`。
- 设定与连续性：只在获授权时改 `story_bible/`、`continuity/` 对应文件；不自建新目录、不新增体系文件。
- 不覆盖已有正文，除非用户明确要求改这一回。改稿保留原稿另存或另记，不悄悄替换。

## 二、篇幅

- 每回平均约一万五千字，是未来目标，随事情轻重伸缩；不为凑字数增加反复说理、求援、赶路或等候。
- 一次写不完就在回内分段推进，不把同一件事拆成两回重复启动。

## 三、交稿前审校（八维）

逐维至少问两句，把发现写成清单，交稿时一并说明：

1. **正典**：有没有违反 `MASTER_PROMPT.md`、`09_不可更改设定.md`、`12_命运线与终局灾变.md`？有没有把待审规划写成已发生？
2. **力量**：第一卷是否始终按凡人的身体条件写含章？后卷只有在黑莲入体之后才核对相应档次的护体、修复与护魂；有没有临时削弱、降智、能力遗忘？
3. **信息**：每个人只知道他该知道的；知情差有没有保留？幻觉、传讯、梦境有没有越界？
4. **时空**：日期、历时、行程、伤势恢复是否对得上 `continuity/时间连续性.md`？
5. **因果**：每一步的结果是否由前面的人与事推出？谁有效反制、付出什么、把什么带到下一回？
6. **人物**：遮名测试过不过？群戏有没有变成轮流表态？称谓对不对？
7. **战斗**：目标、空间、战法差异、有效攻守转换、不可逆结果是否齐备？伤势是否延续？
8. **语言**：是否自然、明白、有金庸式叙述的味道？有没有自造简称、AI 腔、主题句外露？

## 四、审校记录格式

在 `reviews/` 新建一篇，写清：

```
# 第X回 审校记录（YYYY-MM-DD）

## 本回范围与授权
## 硬约束核对（力量 / 信息 / 时间 / 因果）
## 逐场问题
## 语言与文风问题
## 需要用户确认的事项
## 结论（可交稿 / 需改 / 待确认）
```

审校意见是建议，不是已完成的事实；用户不认可的修改不擅自落在正文里。

## 五、连续性更新规则

**只有正文实际写成、并经用户认可之后**，才更新连续性。规划未写成的不登记为已发生。

需要时按顺序更新：

1. `continuity/人物状态.md`：本回结束时各人在哪里、知道什么、关系有何变化。
2. `continuity/时间连续性.md`：本回实际用了多少时间、接在哪个锚点后。
3. `continuity/伤势与恢复.md`：新增伤势、恢复程度、对动作的影响。
4. `continuity/力量变化.md`：只在力量档次或运用方式真的变化时改；不得新增档次。
5. `continuity/伏笔清单.md`：新埋下的、已接上的、还不能揭的。
6. 相关 `story_bible/` 条目：只在用户确认的新事实落定后改，并保留"这是已写事实"与"这是规划"的区分。

更新前先读一遍原文件，保留原有格式与用词；改了哪些地方，在回复里说明。

## 六、交付内容

一次交付至少包含：

1. 正文或大纲文件（写清路径）。
2. 本回自检结论：哪些硬约束已核对、哪些地方做了取舍。
3. 仍需用户确认的空白（如有）。
4. 连续性是否需要更新、更新了什么。

不要把"已完成"说成"已完美"；有拿不准的地方，明说。

## 七、禁止

- 未经授权自动续写下一回；
- 把资料稿或规划登记成已写正文；
- 改连续性档案来伪装正文已经重写；
- 把待确认内容以"暂定"名义写进正文；
- 只报"已写完"，不交代核对与空白。
